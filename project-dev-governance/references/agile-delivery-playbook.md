# 项目开发敏捷方案

## 目标

在需求不稳定、模块并行、跨系统联动的项目中，保持开发节奏可控，而不是把敏捷理解为无限制变更。

## 默认节奏

- 双周迭代
- 三线并行：经管、安全、APP
- 每个迭代固定四个检查点：
  - 需求评审
  - 方案评审
  - 联调评审
  - 发布评审

## 需求分流

将新增需求放入以下三类之一：

1. 原范围补全
2. 下期迭代候选
3. 正式变更项

以下情况默认判定为正式变更项：

- 新增模块
- 主流程重构
- 重大统计口径变化
- 新第三方系统集成
- 权限模型重定义

## 迭代内节奏

1. 第 1-2 天：需求澄清与任务拆分
2. 第 3-8 天：开发与自测
3. 第 9-10 天：联调与测试
4. 第 11-12 天：修复、回归、发布
5. 第 13-14 天：验收与下期准备

## 验收原则

- 每个迭代都要有可演示结果。
- 每个阶段都要有小验收，不等最后一次总验收。
- 经管模块优先按业务域验收，不按页面验收。
